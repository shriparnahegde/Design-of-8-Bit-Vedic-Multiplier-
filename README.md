# Design-of-8-Bit-Vedic-Multiplier-
This repository features the RTL design and functional verification of an 8-bit Vedic Multiplier in Verilog. Utilizing the Urdhva Tiryakbhyam algorithm, its hierarchical architecture and optimized addition trees minimize carry propagation delay to deliver fast, high-performance multiplication.


the RTL design and functional verification of an 8-bit Vedic Multiplier implemented in Verilog. The design leverages the highly efficient Urdhva Tiryakbhyam (vertically and crosswise) algorithm to perform fast multiplication. By structuring the architecture hierarchically and utilizing optimized addition trees, this project demonstrates a strong focus on reducing carry propagation delay and improving overall computational performance.

# Design ArchitectureThe multiplier is built using a bottom-up hierarchical approach:Base Module (2x2): The foundational block that performs 2-bit multiplication using basic logic gates.  Intermediate Module (4x4): Instantiates four 2x2 multipliers. It utilizes an optimized addition tree to handle partial products and reduce carry delay.  Top Module (8x8): Instantiates four 4x4 multipliers. Similar to the 4x4 block, it uses an advanced addition tree for final partial product mapping to generate the 16-bit output.  

# Verification & SimulationThe design is verified using a robust, self-checking testbench to ensure functional accuracy. 
Testbench Features:Directed Testing: Includes specific edge-case scenarios, such as all zeros, maximum values (255 x 255), and mixed hex values.  Automated Random Testing: Runs multiple iterations of randomized inputs using the random system task to ensure comprehensive coverage.  Self-Checking Mechanism: A dedicated task (check_result) automatically computes the expected product and compares it against the simulation output. Any mismatches trigger an error log with the exact simulation time.  Simulation Results:
The design was successfully simulated on EDA Playground. As shown in the included waveform screenshot, all signals (including intermediate partial sums mid_sum, sum2, sum3) resolve correctly, and the automated verification reported zero errors across all directed and randomized tests.
